从一次本地部署开始

完整部署文档 ↗
1

启动基础网关

Linux 
git clone --branch litellm_account_auth \
  https://github.com/nodeloc/cocaapi.git
cd cocaapi/deploy/cocaapi
python3 generate_secrets.py
sed -i 's|https://cocaapi.com|http://localhost:4000|' compose.yaml
docker compose -f compose.yaml up -d

示例用于 Linux 本地部署，需要 Docker Compose 与 Python 3。公网部署时，将 PROXY_BASE_URL 改为自己的 HTTPS 域名，首次启动后等待健康检查完成

2

添加上游与个人密钥

Admin UI

打开 http://localhost:4000/ui/，使用生成的 .env 中的管理员账号登录

添加已授权的提供商与上游密钥，设置一个模型别名，例如 my-model，再创建供应用调用的虚拟密钥

配置模型授权访问创建 Key

初始模型列表为空。上游 API 调用由提供商计费，应用应使用虚拟密钥

3

发送第一个请求

curl http://localhost:4000/v1/chat/completions \
  -H "Authorization: Bearer $COCAAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-model","messages":[{"role":"user","content":"你好，CocaAPI"}]}'

先将虚拟密钥设置为环境变量 COCAAPI_API_KEY，并将 my-model 替换为你配置的模型别名。Python 与 Node.js 需先安装对应的 openai SDK

需要用户中心与钱包？基础网关之外，请按 账号扩展 与 计费扩展 文档构建对应镜像，配置 auth.env 并使用 compose.auth.yaml

GOOD TO KNOW

部署之前
了解这些

CocaAPI 和 LiteLLM 是什么关系？

CocaAPI 在 LiteLLM 的基础上扩展用户账号、钱包、兑换码与个人网关页面。统一模型接口、路由和管理后台来自 LiteLLM，源码保留在当前项目仓库中

开源许可是什么？

仓库 LICENSE 将 enterprise 目录以外的内容置于 MIT 许可下，enterprise 目录适用独立许可。使用、修改和分发前，请阅读 完整 LICENSE

部署后就能调用所有模型吗？

需要先配置已授权的上游服务、模型和 API Key。基础部署的模型列表为空，虚拟密钥的模型权限与预算也需要由管理员配置。上游服务会按其规则收费

账号、邮件和支付能直接使用吗？

用户中心和钱包需要构建并部署扩展镜像。邮件与第三方登录需要对应服务凭据，USDT 支付网关仍需接入具体支付适配器，不应视为已开通的收款能力

自托管时，数据会发到哪里？

网关与存储运行在你的服务器上。远程模型调用会将请求发送到你配置的提供商；如需控制日志留存、访问权限或使用本地模型，请按自己的部署要求配置
