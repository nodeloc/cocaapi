# 余额、兑换码与充值

用户入口为 `/account/wallet/` 和 `/account/orders/`，管理入口为 `/ui/commerce/`。界面复用现有主题、卡片、表格和表单组件。只有完整代理管理员可以查询所有账户、调整余额、生成及停用兑换码和复核充值订单，只读管理员与客户 Cookie 均没有管理权限

额度按 USD 记账，1 USD 为 1,000,000,000 整数 units。数据库使用 BIGINT，API 将 units 序列化为字符串，前端使用 BigInt 展示。充值、兑换面额及人工调整的单次金额范围为 0.01 至 100000 USD，最多两位小数。余额不能为负，累计入账、扣减及余额均有整数上限

API 调用已接入钱包预扣与结算。注册客户的个人 Key 和 Playground 均从同一钱包扣费，费用沿用管理员配置的 LiteLLM 模型单价，没有额外倍率。充值和兑换不会开放原生模型权限或提高原生 API 预算，新客户仍需管理员授权模型与调用预算

## 兑换码

在 `/opt/cocaapi/auth.env` 配置独立的 `COCAAPI_REDEMPTION_SECRET`，使用至少 32 字符的随机值，与数据库一同备份。这个值不能随认证密钥轮换，更换它会使已发出但未使用的兑换码失效。未配置时兑换和发码不可用

每批生成 1 至 100 个随机兑换码，支持面额、名称、有效期和批次停用。明文仅在首次生成响应中返回，可以在页面一次性导出 TXT；数据库只保留带域隔离 HMAC 摘要和尾号。列表和审计不包含完整兑换码。创建批次请求的幂等键重放返回冲突，不重复发码，响应丢失时不能恢复明文，应停用该批次后重新生成

兑换要求已验证邮箱和有效会话。批次、兑换码、客户及钱包按固定顺序锁定，流水和核销状态同事务提交。同一用户重试同一码返回原流水，其他用户不能再次兑换。停用与核销使用同一批次锁，已经兑换的额度不会因批次停用撤销

## USDT 网关适配

生产默认 `UnconfiguredGateway`，网络列表为空，下单及回调返回 503。没有模拟支付或手工标记已支付的接口。选定网关后，实现 `litellm/models/commerce_payment.py` 的 `PaymentGateway`，通过 `payment_routes.get_gateway` 注入。适配器必须使用真实官方文档及商户凭据，实现创建支付、主动查单和原始请求验签，凭据仅保存在服务器受限环境文件

网络标识预留 `tron`、`ethereum`、`bsc`，仅向用户开放实际支持的网络。适配器返回明确的商户账户、商户订单号、外部支付 ID、USDT 报价、网络、到期时间及允许的 HTTPS 支付域名。服务端校验这些字段和支付时间，发生不匹配时进入待核查状态，不入账。付款页面返回和客户端参数均不能确认到账

创建操作先保存订单意图，再调用外部服务。超时后保留 `creating` 状态，使用同一商户订单号查单恢复，不能随意重新创建。若进程在保存意图后、调用网关前退出，外部可能没有订单；接入具体网关时必须确认其支持同商户订单号幂等创建，或提供权威的不存在结果与恢复流程。当前接口不会猜测外部状态或自动重建此类订单

支付通知验签后仍需主动查单，核对订单归属、商户账户、外部 ID、资产、网络和精确 Decimal 金额。到账、钱包、唯一业务流水、外部事件和审计在同一事务提交。重复通知与用户/管理员并发查单只入账一次。管理员只能发起查单，不能直接增加订单支付状态

## API 调用计费

启用账号服务（配置 `COCAAPI_AUTH_SECRET`）后，客户必须邮箱已验证、账号有效、可用余额大于零且没有待补缴费用才能调用。调用前按输入、输出上限及所有已配置 fallback 的最高预估费用冻结额度，余额不足返回 HTTP 402 / `insufficient_balance`，不会访问上游。未提供输出上限时，生成请求使用 4096 Token 上限；建议客户端按实际需要指定较小的上限，减少冻结

在最终部署发送前再次检查有效请求和最终模型计价，服务端增加提示词、工具或重路由导致预估上升时，需在事务内补足冻结并记录发送状态，否则拒绝调用。钱包锁和持久请求 ID 防止多 worker 并发超支，客户端 user、metadata 和调用 ID 不能指定扣款归属或复用另一笔预扣

支持文本 Chat Completions、Completions、Responses、Anthropic Messages 和 Embeddings，包含原生流式费用回调。成功后按 LiteLLM 原生实际费用结算，退回未用额度，唯一业务流水使重复回调不重复扣费。缓存命中按原生零费用结算，但调用前仍需满足预扣条件。内部用户与代理管理员不属于客户钱包，不受新增钱包扣费影响

客户不开放团队 Key、批处理、文件、图像、音频、实时连接、通用透传和异步后台调用。无法完整预估的远程提示词模板、服务端历史引用、多媒体、内置付费工具、动态路由参数、客户端单价/供应商覆盖、缓存写入控制及 premium service tier / fast speed 请求拒绝。配置缺少价格、有效部署信息或存储不可用时返回 503，不能降级为免费调用。原生模型权限、Key 限额、用户预算和速率限制继续执行

明确未发送的失败会释放预扣。非流式上游明确拒绝也会释放；已经输出、流式失败、超时、断连、进程退出或结算失败等费用不明的请求保留冻结，不能按经过时间自动退款。异常实际费用超过余额时记录待补缴，禁止继续调用，后续充值或兑换优先还清欠费。余额页展示可用、调用冻结、待补缴及 API 扣费流水，不补扣升级前的历史调用

## 冻结复核与维护

仅服务器运维可以核对超过一小时的冻结记录，没有公开的手工退款接口。先结合 `native_request_id`、原生日志和上游账单确认实际费用，1 USD = 1000000000 units，然后执行带操作者和原因的核对，流水与审计同事务保存。重复同金额核对不重复扣费，变更已结算金额返回冲突

```bash
docker exec cocaapi-gateway-1 python3 -m litellm.proxy.commerce.billing_reconcile --list
docker exec cocaapi-gateway-1 python3 -m litellm.proxy.commerce.billing_reconcile --request-id REQUEST_ID --actual-units VERIFIED_UNITS --actor ADMIN_ID --reason 'Verified against native and provider records'
```

计费上线后，不可直接回滚到不认识 usage 流水和 debt_units 的旧镜像。应保留当前兼容镜像与数据库，在 `auth.env` 设置 `COCAAPI_BILLING_MAINTENANCE=true` 并重建 gateway，使客户计费路由返回 503，钱包查询、充值及核对继续可用；排查后恢复 false。不要删除冻结、扣费流水或回退数据库约束，禁止用旧版本的入账逻辑处理欠费
