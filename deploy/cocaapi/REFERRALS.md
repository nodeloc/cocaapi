# 邀请有礼

用户入口为 `/account/referrals/`，后台入口为 `/ui/commerce/referrals/`，两处均沿用原后台组件并支持中英文。用户生成固定邀请链接，受邀用户打开 `/account/register/?ref=邀请码` 后，邮箱注册和 GitHub、Google、NodeLoc OAuth 都会携带邀请上下文。注册前可以取消邀请

## 活动规则

活动默认关闭，邀请人和受邀人金额均为零。完整代理管理员在“账户与充值 / 邀请有礼”分别填写双方的 USD 额度，金额最多两位小数，双方均大于零后才能启用。只读管理员和普通用户不能修改或读取后台配置，用户只能查看自己的邀请记录，受邀用户以编号显示

邀请关系只在新账号创建的事务中绑定。邮箱验证成功或 OAuth 新账号授权注册完成后，双方各获得一次额度。OAuth 证明第三方身份，不修改原邮箱验证标志，也不改变现有模型权限、用户组、余额检查或 API 调用限额。已有账号登录、重复邮件验证、绑定新的 OAuth 账号均不会补绑或重复领奖

金额按注册时的活动配置保存。活动关闭时的新注册记录不补发；开启期间已经记录的待验证邀请，即使之后调整金额或关闭活动，仍保留原金额。邀请码无效或邀请人停用时不能绑定，注册页可取消邀请后继续普通注册

奖励使用钱包现有 USD 记账单位，到账后按原逻辑抵扣待补缴费用并用于调用。双方流水使用 `referral` 类型和独立唯一业务键，关系行锁和事务保存点保证不会重复入账或留下单边奖励。如果钱包达到资金上限，两笔奖励均撤回到待处理状态，身份验证仍可成功，后续登录会再次尝试处理。账号停用的邀请不发放
