# 用户组、模型组与调用倍率

管理员入口为 [账户与充值 / 分组与倍率](https://demo.cocaapi.com/ui/commerce/groups/)，复用原后台的 Page、Card、DataTable、Select、MultiSelect 和 Checkbox 组件

在“用户组”添加组并命名，在“模型组”选择已有的公开模型，再在“组间倍率与禁用”选择两组、填写倍率和是否允许调用。先点击“应用规则”，填写配置变更原因，再点击“保存分组配置”。下方“用户归组”可按邮箱或用户 ID 查询用户，选择目标用户组并填写原因后保存

现有用户和新注册用户默认属于 `default` 普通组。没有显式归组的模型属于普通模型组，每个公开模型只能属于一个模型组。没有特殊规则的组合默认允许、1 倍。保留默认组不能删除，在用用户组须先调整其用户的归属才能删除。名称可以修改，稳定 ID 不随名称变化

分组只叠加倍率和禁用规则，原生账户及个人 Key 的模型权限仍是上限。归组不会授予其他模型，也不会取消原生预算、速率和有效期限制。禁用在服务端预扣之前检查，对已有 Key 同样生效，客户模型列表会过滤被禁用的模型

## 费用与快照

调用费用为基础费用乘倍率，支持 0 至 1000，最多六位小数。使用百万分整数计算，结果向上取整到纳美元。0.8 表示八折，2 表示两倍，0 倍仍要求正余额、没有欠费，并保留原有限制

倍率同时用于预扣、回退部署追加预扣和最终结算。在客户行锁内读取归组与配置，保存请求公开模型所属组、组名、配置版本、归组版本和倍率快照。调用开始后调整模型归组、倍率或用户归组，不改变这一笔调用的倍率。上游回退沿用请求开始时的倍率，基础报价仍覆盖潜在回退成本

余额流水展示当时的组别、倍率与基础费用，客户用量和日志关联钱包实际费用。关联使用每次调用私有的随机标识，并按用户及 Key 核对。同一调用的重试日志只展示一次最终钱包费用，必要关联字段不受可选元数据裁剪影响，其他诊断字段继续遵守裁剪配置。旧流水保持原金额，不补造历史分组

原生管理后台的供应商成本统计及原生 Key、账户预算计数继续采用原生费用，钱包实际扣减采用分组倍率。充值、兑换码和人工调整金额不应用调用倍率。人工核对未完成冻结时，`billing_reconcile --actual-units` 仍填写最终应扣金额，不再乘倍率

## 存储与接口

配置追加保存于 `CommerceBillingConfiguration`，修改须提供期望版本和原因，事务 advisory lock 串行化配置与归组写入。归组使用独立版本防止覆盖其他管理员的修改，审计保存操作人、原因、调整前后的组别、版本及当时配置版本

以下接口均要求完整代理管理员 Bearer 凭据，只读管理员和客户 Session 不能调用

| 接口 | 用途 |
| --- | --- |
| `GET /commerce/admin/v1/billing-groups` | 当前配置及版本 |
| `PUT /commerce/admin/v1/billing-groups` | 保存分组、模型成员与组合规则 |
| `GET /commerce/admin/v1/billing-groups/catalog` | 可配置的公开模型名 |
| `GET /commerce/admin/v1/billing-groups/members` | 查询用户归组，支持分页 |
| `POST /commerce/admin/v1/billing-groups/members/{user_id}` | 按期望归组版本调整用户 |

参考 new-api 提交 `d0abbf6e0d33552a41c402d9b1fadbaff27cf40d` 的 [组倍率](https://github.com/QuantumNous/new-api/blob/d0abbf6e0d33552a41c402d9b1fadbaff27cf40d/setting/ratio_setting/group_ratio.go) 与 [计费参数](https://github.com/QuantumNous/new-api/blob/d0abbf6e0d33552a41c402d9b1fadbaff27cf40d/relay/helper/price.go)，独立实现配置、快照与事务计费
