# 客户 API 网关

客户入口为 [用户概览](https://cocaapi.com/account/home/)。账号、余额、充值和安全设置保留，新增个人 API 密钥、已授权模型目录、Playground、用量统计、请求日志、调用限额和接入文档。菜单复用管理后台模板。原后台功能到客户页面的完整映射见[实施计划](../../docs/superpowers/plans/2026-11-01-customer-gateway.md)

## 权限与数据

客户接口位于 `/account/api/v1/gateway`，只使用客户 HttpOnly 会话。服务端从 Session 取得 user_id，用户不能指定其他用户、团队、上游地址或更高预算。密钥列表只返回本人非团队密钥的白名单字段，操作 ID 加密，不公开原生密钥 hash。新密钥明文仅在创建后显示一次，不写入浏览器存储。创建及删除要求近期身份验证，写操作沿用 Origin、CSRF 和限流

模型授权复用原生校验，支持模型名称、通配符、模型访问组和 `all-proxy-models`。`no-default-models` 始终优先拒绝。目录不公开上游 URL、部署参数或提供商凭据。密钥创建经过原生生成接口，以保留平台的 upperbound 和 policy 校验；生成后再次核对个人归属、llm_api 路由以及空团队、组织、项目、Agent 和对象权限。默认配置注入其他权限时立即通过原生接口撤销，不把密钥交给用户，返回 `personal_key_unavailable`，需要管理员检查默认密钥设置

账号预算按原生预算周期执行，不复制成密钥的一次性终身预算。密钥仍受平台默认密钥限制及原生用户、模型、速率和全局限制。新注册客户继续保持零预算及无默认模型，不能自行抬高额度。钱包余额与原生 API 预算仍独立，充值不会自动提高 API 预算，USDT 网关及钱包调用扣费保持原来的未接入状态

Playground 只接受本人的个人密钥及当前已授权模型，使用原生推理鉴权与调用链，限制输入长度和输出 Token，不接受任意路由、工具或请求配置。日志和用量依据密钥归属关联，不信任请求中可伪造的 user 字段；删除后的密钥通过原生删除档案保留历史。统计按 UTC 日期和最近 7/30 天查询，仅计入模型调用，排除模型列表等无模型请求，不返回正文、上游地址或内部元数据

客户删除路径在原生删除后补充 `evict_and_broadcast`，清除本地认证对象及 Redis，并广播其他 worker。原生删除档案和审计保留。该补充仅在删除成功后执行，使用现有广播的异步 best-effort 机制，不新增撤销存储或更改全站缓存配置

服务器 Caddy 2.6.2 会把 `>Cache-Control` 当作字面头名称，账号静态页面因此缺少预期缓存头。配置已改用显式 `defer`，通过 Caddy 适配后的 JSON 及实际 HTTPS 响应验证账号页面和接口的 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`，无需升级 Caddy

## 发布与使用

升级前数据库、环境、Compose、Caddy 和加密登录配置指纹备份位于 `/opt/cocaapi/backups/customer-gateway-20261101T153240Z/`，数据库归档通过 `pg_restore --list`，未做完整恢复演练。本次没有新增 schema 或迁移。先在端口 4001 预发布并验证公网，再切回 4000 主网关；OAuth 加密配置及 revision 按备份指纹核对

生产不创建测试客户、密钥、余额或模型。发布前查到已配置模型数量为 0，需要管理员在 Models + Endpoints 添加模型，并在 Internal Users 为对应 commerce 用户分配模型和调用预算，客户才能创建可用密钥。不要把客户提升为代理管理员

回退时恢复上述 `.env` 的 COCAAPI_IMAGE 并重建 gateway。无需回退数据库结构；保留原有 auth.env 主密钥，使客户会话与加密 OAuth 配置继续匹配
