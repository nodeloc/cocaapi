# Wallet API Billing Implementation Plan

**Goal:** 客户钱包支付 API 调用费用，余额不足不得调用上游

**Architecture:** 在原生鉴权后限制客户可计费路由，用原生请求预检和费用回调接入 PostgreSQL 持久预扣与结算。锁定客户及钱包后检查可用余额，成功后按原生计价结算，重复回调不重复扣费。原有原生预算和模型权限继续执行

**Tech Stack:** FastAPI、LiteLLM 原生 hooks 和费用计算、PostgreSQL 事务、现有整数 USD 钱包、原后台 UI 组件

**Spec:** 用户要求「接下来把用户余额和 API 调用扣费打通，余额不足时禁止调用」

## 约束

客户归属从原生鉴权对象取得，不能接受请求中的 user、金额、预扣 ID 或模型单价。调用价格沿用已配置的模型计价，不新增倍率。现有内部用户和管理员计费不变。支持可预估的文本 Chat、Completions、Responses、Messages 和 Embeddings，其他客户调用拒绝，不允许通过透传、批处理、后台任务或实时连接绕过钱包。金额按 1 USD = 1000000000 units 向上取整

预扣不会写作实际消费。进程中断或无法确定实际费用时保留冻结额度，不按超时自动退款。实际费用异常超过冻结额时记录欠费并禁止继续调用，后续入账优先抵扣欠费。原生调用预算为零的客户仍需管理员开通调用限额，充值不绕过管理员限制
